# Adding a machine from photos

Operate the local tools yourself. Inspect the images with your vision capability. Use the physics library to calculate the forces. There is no model service in the application.

1. Run `python -m resistance_curves prepare bottom.jpg middle.jpg top.jpg --out work/poses`. Use the supplied order from the **true full-stretch start (0% travel, unloaded/resting end of the rep — NOT an already partially contracted mid-rep frame)** to the **peak-contraction finish (100% travel)** of the lifting phase. Read the generated prompt and open every numbered square image.
2. Write `work/poses/observation.json` following that prompt. Mark the visible points in the square image coordinates. For `plates`, mark the actual **center of mass of the stacked weight plates** (center of the plate hubs where the plates sit on the sleeve — NEVER the tip or midpoint of a protruding unloaded loading pin; inspect the automatic `Plates hub zoom` inset on every review overlay to verify). For a freely pivoting handle yoke (on a lever or belt cam), mark `grip` at the rigid mounting pin on the rotating arm and `pull_toward` at the hand grip (two-force link); never mark a pivoting hand grip as rigid on the cam. Reject oblique camera views where circular weight plates are strongly foreshortened or where an axial offset along the pivot (such as an outboard plate horn vs. an inboard pad) projects across the lever plane. Trace the entire load path and explain uncertain identifications in `evidence`. Record the input filenames or photo identifiers in the same order. The rigid lever sample under `catalog/machines` contains a full working observation.
3. For an isolation movement, identify the joint center and proximal/distal segments. Mark an in-plane metric reference in every image and record the length and its basis. An assumed length needs an explicit assumption and a plausible range in the evidence. Without a credible reference keep the force estimate and omit the anatomical fields. Compare plausible alternatives when an uncertain landmark changes the conclusion. Check the force opposes the lifting stroke and document which limb bears it. Use movement “compound” for multi-joint exercises.
4. Run `python -m resistance_curves estimate work/poses/observation.json --plate-kg MASS --out work/review`. Open BOTH the labeled overlays (`landmarks-*.png`, including the magnified `Plates hub zoom` inset) AND the automatic `pivot-check.png` (50/50 start+finish ghost overlay). Verify on `pivot-check.png` that: (a) the red `Pivot` sits squarely on the stationary bearing intersection of the ghosted moving arm and agrees with the green concentric-circle kinematic center, and (b) Pose 1 starts at the true stretched bottom of the rep rather than mid-stroke. For `belt_cam` machines, cross-check the static belt/cam curve against direct conservation of work ($\Delta y_{\text{plates}} / \Delta s_{\text{hand}}$) and kinematic rotation ratio ($\Delta\theta_{\text{load}} / \Delta\theta_{\text{cam}}$). If a pivot, belt tangent, plate hub, joint or scale reference misses its target, correct the observation and use a new review directory. Report an unresolved mechanism when evidence is insufficient.
5. Save a reviewed estimate using `python -m resistance_curves record work/poses/observation.json --slug MACHINE-ID --name 'Machine name' --manufacturer 'Manufacturer' --movement elbow-flexion --plate-kg MASS --source 'Photo identifiers, setup, load sharing and limitations'`. The record command stores a fitted resistance function alongside the observations. After correcting an existing record, run `python -m resistance_curves fit catalog/machines/MACHINE-ID.json --write` to refresh its coefficients. Review the sample error and any sparse midrange assumptions. Add an appropriate strength profile under catalog/strength if measurements exist. Keep strength measurements independent from machine force. When a starting resistance is known, record its measurement or manufacturer source in base_resistance, with the workarm basis and units in kgf. Include finish_kgf when supported by evidence.
6. Run the tests and the Hugo build described in README.md. Review the git diff including new files. Only commit photographs or identifying information when authorized. Version the JSON and templates, with generated HTML kept in the build output.

## Adding a machine from a 3D model

Use a locally available upstream asset and record the manufacturer's product URL or CAD source. Follow the model commands in README.md. Open the side, end and top renders and inspect part names, dimensions and world transforms in model.json. Identify which parts actually move, the loaded plate center, the contact point and the direction of gravity. Choose the side view perpendicular to the plane of rotation. Annotate metric coordinates or node-local points directly where possible. Cite the source of travel limits for a static lever. For a cam, obtain multiple actual posed assemblies with visible belt tangents, and check the handle attachment is rigid relative to the cam. Export individual poses from animated assets. If the model is a single decorative pose or hides the relevant joints, retain it as supporting evidence and use the photo workflow for the missing positions. Review generated overlays before recording a curve. A catalog build uses the saved landmarks and runs independently of the CAD file.
